# BUG-044 - Sinal antifraude por IP confiava em cabeçalho enviado pelo cliente

- **ID:** BUG-044
- **Data:** 2026-10-16
- **Severidade:** BAIXA (o sinal só gera alerta; nada é bloqueado)
- **Perfil afetado:** admin (fila de suspeitas)

## Passos para reproduzir
1. Ativar cupons de teste enviando `CF-Connecting-IP` ou `X-Real-IP` forjados.
2. O sinal "vários testes do mesmo IP" pode ser evitado (IP diferente a cada chamada) ou forjado contra terceiros.

## Causa raiz
O IP é lido de `cf-connecting-ip`/`x-real-ip` antes do endereço do socket (mesma regra usada nos cliques de indicação da F5). Na VPS, o nginx define `X-Real-IP`, mas não remove um `CF-Connecting-IP` enviado pelo cliente.

## Correção (arquivos alterados)
Pendente: no nginx, `proxy_set_header CF-Connecting-IP "";` (ou passar a usar só o `X-Real-IP` definido pelo proxy). Até lá, o impacto fica limitado porque IP/dispositivo só geram ALERTA (D6), e a unicidade do teste usa a identidade da conta + telefone normalizado.

## Teste de regressão adicionado
`v6-antifraude.mjs` cobre o sinal por dispositivo e a fila de revisão; o teste do cabeçalho entra junto com a correção.

## Lição / armadilha
Nunca confiar em cabeçalho de IP que o proxy não sobrescreve.
